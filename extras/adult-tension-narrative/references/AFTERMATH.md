# Aftermath

## ATN-AFTERMATH-001 — Derived window

`AFTERMATH` is a derived narrative window, not a one-turn timer and not persistent state.

Use it while the current scene is still directly processing immediate consequences of the just-ended `ACTIVE` sequence.

It may last multiple turns when the conversation remains in that window.

## ATN-AFTERMATH-002 — Facts versus presentation timing

The existing Adult Tension / Native RP Runtime owns aftermath **facts** and committed consequences.

This Skill owns only aftermath **presentation timing**.

Use the reduced stack:

1. physical continuity;
2. emotional continuity that is already supported;
3. character integrity;
4. relationship-context plausibility;
5. POV consistency;
6. literary breathing;
7. anti-slop.

Do not re-stage, duplicate or re-commit a consequence that already occurred.

Do not force every aftermath consequence into the final `ACTIVE` response merely because older prose guidance expects a closure beat.

A valid aftermath may be distributed across multiple turns while the direct post-scene consequences remain the focus.

Do not keep the full ACTIVE directness policy running by inertia.

## ATN-AFTERMATH-003 — No automatic relationship conclusion

Do not automatically infer:

- a relationship upgrade;
- reconciliation;
- commitment;
- emotional closure;
- a new preference;
- a new permission;
- private player feelings.

Such changes require actual story evidence and normal runtime staging.

## ATN-AFTERMATH-004 — Exit conditions

Re-derive and normally exit `AFTERMATH` when any of these occurs:

- scene/location changes;
- participant set materially changes;
- explicit time skip;
- a new unrelated objective becomes primary;
- the user switches to OOC/runtime control;
- the direct post-scene consequences are no longer the focus.

Return to `INACTIVE` unless current evidence supports another phase.
